# Шаблон локации PaperFly

Из этого репозитория создаётся проект новой локации. Художник работает в нём, а игра подключает
локацию пакетом: в игру попадает только папка `Assets/Location`.

## Что где лежит

```
Assets/
├── Location/            ПАКЕТ ЛОКАЦИИ — уходит в игру
│   ├── package.json     имя и версия пакета, ключевое слово paperfly-location
│   ├── .gitattributes   правила LFS пакета (без них модели придут в игру указателями)
│   ├── Location-Art.prefab   основа: корень локации, на него ссылается игра
│   ├── Materials/  Models/  Textures/   только внешний вид локации
└── Workspace/           РАБОЧЕЕ МЕСТО — в игру не попадает
    ├── Scenes/Preview.unity  сцена просмотра: камера, свет, Volume
    └── Rendering/            настройки URP этого проекта
```

Общие настройки рендера (URP Asset, Renderer, профили Volume), пресеты импорта и проверки
приходят из пакета **PaperFly Render Kit**. Поэтому картинка у художника и в игре одинаковая.
Render Kit обновляется сам при открытии проекта, push с устаревшим Render Kit не проходит.

Подробный процесс и регламент — в документе «Процесс добавления и поддержки локации в игру».

## Создать новую локацию

1. На GitHub в этом репозитории нажмите **Use this template → Create a new repository**.
   Имя — `PaperFly.Location.<Имя>`, репозиторий приватный.
2. Склонируйте репозиторий в Fork и откройте папку в Unity Hub. Версия Unity — из `ProjectSettings/ProjectVersion.txt`.
3. В `Assets/Location/package.json` замените:
   - `name` — `com.paperfly.<имя>` (строчными, без пробелов);
   - `displayName` и `description`.

   Ключевое слово `paperfly-location` не удаляйте: по нему Render Kit узнаёт пакет локации.
4. Закоммитьте и отправьте. При открытии проекта Render Kit сам поставит хук проверки перед отправкой.

## Правила

- **Всё, что нужно игре, — только в `Assets/Location`.** Ссылка из пакета на файл в `Workspace`
  или в другом месте проекта — ошибка: в игре она окажется пустой. Её найдёт проверка перед отправкой.
- **Не копируйте файлы из проекта игры вместе с `.meta`.** У копии будет тот же GUID, что у файла
  игры, и при подключении они столкнутся. Общие шейдеры и материалы должны лежать в Render Kit.
- **Объекты основы не переименовывайте и не удаляйте без нужды.** Правки игры привязаны к ним.
  Что пострадает, покажет «Подготовить выпуск».

## Работа

1. Положите FBX в `Assets/Location/Models`, текстуры — в `Textures`. Render Kit сам наложит пресеты
   импорта и покажет найденные проблемы в окне **PaperFly → Валидация → Отчёт**.
2. Материалы без привязки предложит привязать или извлечь окно **PaperFly → Валидация → Материалы моделей**.
3. Соберите локацию в `Location-Art.prefab`, проверяйте вид в `Workspace/Scenes/Preview.unity`.

## Выпуск версии

1. **PaperFly → Выпуск → Подготовить выпуск**: поднимите версию, окно запишет её в `package.json`
   и манифест выпуска.
2. В Fork закоммитьте `package.json` и `release-manifest.json`, поставьте на этот коммит тег
   с номером версии (например, `1.0.0`) и отправьте вместе с тегом. Перед отправкой хук проверит пакет.

## Подключение в игре (для разработчика)

В `Packages/manifest.json` игры:

```json
"com.paperfly.<имя>": "https://github.com/<владелец>/PaperFly.Location.<Имя>.git?path=/Assets/Location#<тег>"
```

Дальше — окно **PaperFly → Приём → Приём локаций**: проверка поставки и кнопка «Принять».
Версию потом можно менять в **PaperFly → Приём → Версии локаций**.
