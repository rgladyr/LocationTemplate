# Шаблон локации PaperFly

Проект одной локации. Художник работает в нём, а игра подключает локацию пакетом:
в игру попадает только папка `Assets/Location`.

## Подключение в игру

Адрес пакета локации — скопируйте его целиком и вставьте в игре в **Window → Package Manager → + →
Add package from git URL**. Версию потом выберите в окне **PaperFly → Приём → Версии локаций**.

<!-- paperfly:game-package -->
```
https://github.com/<организация>/PaperFly.Location.<Имя>.git?path=/Assets/Location
```
<!-- /paperfly:game-package -->

Адрес и заголовок этого файла Render Kit заполняет сам при открытии проекта в Unity.

## Что где лежит

```
Assets/
├── Location/            ПАКЕТ ЛОКАЦИИ — уходит в игру
│   ├── package.json     имя и версия пакета, ключевое слово paperfly-location
│   ├── .gitattributes   правила LFS пакета (без них модели придут в игру пустыми)
│   ├── Location-Art.prefab   основа: корень локации, на него ссылается игра
│   ├── Materials/  Models/  Textures/   только внешний вид локации
└── Workspace/           РАБОЧЕЕ МЕСТО — в игру не попадает
    ├── Scenes/Preview.unity  сцена просмотра: камера, свет, Volume
    └── Rendering/            настройки URP этого проекта
```

Общие настройки рендера, пресеты импорта и проверки приходят из пакета **PaperFly Render Kit**,
поэтому картинка у художника и в игре одинаковая. Render Kit обновляется сам при открытии проекта.

Подробный процесс и регламент — в документе «Процесс добавления и поддержки локации в игре».

## Создать новую локацию

1. На GitHub в репозитории шаблона нажмите **Use this template → Create a new repository**.
   Имя — `PaperFly.Location.<Имя>`, репозиторий приватный.
2. Склонируйте репозиторий в Fork и откройте папку в Unity Hub. Версия Unity — из `ProjectSettings/ProjectVersion.txt`.
3. При первом открытии Render Kit сам:
   - задаст имя пакета по имени репозитория (`PaperFly.Location.Beach` → `com.paperfly.beach`);
   - выдаст файлам шаблона новые GUID, чтобы в игре они не конфликтовали с другими локациями;
   - заполнит строку подключения и заголовок в этом файле;
   - поставит хуки проверки при коммите и push.
4. Закоммитьте `package.json`, изменённые `.meta` и `README.md` и отправьте.

## Правила

- **Всё, что нужно игре, — только в `Assets/Location`.** Ссылка из пакета на файл в `Workspace`
  или в другом месте проекта — ошибка: в игре она окажется пустой. Её найдут проверки при коммите и push.
- **Не копируйте файлы из проекта игры вместе с `.meta`.** У копии будет тот же GUID, что у файла
  игры, и при подключении они столкнутся. Общие шейдеры и материалы должны лежать в Render Kit.
- **Объекты основы с правками игры не переименовывайте и не удаляйте без договорённости.**
  Правки игры привязаны к ним, и часть придётся повторять вручную.

## Работа

1. Положите FBX в `Assets/Location/Models`. Render Kit сам наложит пресеты импорта и покажет
   найденные проблемы в окне **PaperFly → Валидация → Отчёт**.
2. Материалы, оставшиеся внутри FBX, предложит привязать или извлечь окно «Материалы моделей».
   При извлечении встроенные текстуры кладутся в `Textures`, материалы — в `Materials`.
3. Соберите локацию в основе, проверяйте вид в `Workspace/Scenes/Preview.unity`.

## Выпуск версии

1. **PaperFly → Выпуск → Подготовить выпуск**: введите версию выше последнего тега, окно запишет её
   в `package.json` и манифест выпуска.
2. В Fork закоммитьте `package.json` и `release-manifest.json`, поставьте на этот коммит тег
   с номером версии (например, `1.0.0`) и отправьте вместе с тегом. Принять в игру можно только версию с тегом.
